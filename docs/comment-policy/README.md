# 주석 필요성 정책

이 레포의 주석은 **필요 사유를 한 문장으로 댈 수 있는 것**만 남긴다. 사유를 댈 수 없는 주석은 아무도 검증하지 않은 채 낡아 가고, 읽는 사람의 주의를 필요한 주석과 나눠 가진다. reconciler 모델 `tbm_claude-transcript-viewer-v2-comment-necessity`가 이 디렉터리를 SSOT로 추적한다.

| 파일 | 담는 것 |
|---|---|
| `README.md` (이 문서) | 필요성 시험 · 유지 대상 · 운영 규칙 · 판정 절차 · 범위 밖 · 지문 사각지대 |
| [`ledger.md`](ledger.md) | 판정한 범위(파일 단위)·주석 줄 수·지문·판정 칸의 표 |
| [`passes/`](passes/) | 패스별 제거 목록(불필요 유형)과 유지 목록(주석·묶음마다 필요 사유 한 문장) |

## 필요성 시험

> 이 주석을 지우면, 이 코드를 고치러 온 사람이 틀린 판단을 하거나 그 판단에 필요한 사실을 확인하는 데 상당한 비용을 치르는가?

예라면 그 결과(무엇을 틀리게 되는가, 무엇을 어디서 찾아야 하는가)를 적은 한 문장이 필요 사유다.

- **사유를 한 문장으로 댈 수 없으면 지운다.** 애매함은 보존의 근거가 아니다. 지운 주석은 git 이력에 남는다.
- **사유는 결과를 말한다.** "중요함"·"참고용"·"나중에 필요할 수 있음"은 사유가 아니다.
- **불필요의 흔한 유형**: 코드 재진술, 저장소 문서 재진술, PR·커밋 이력 재진술, 작업 흔적(누가·언제·끝난 TODO·경위), 장식·구분선, 소감·추측, 주석 처리된 코드. 목록은 시험을 대신하지 않는다.
- **더 나은 자리가 있으면 옮긴다.** 이름·타입·테스트·저장소 문서로 옮겨 코드가 스스로 말하게 할 수 있으면 옮기고 주석은 지운다. 옮기는 변경은 같은 PR에 둔다.
- **틀린 주석**은 사유가 있으면 고치고, 없으면 지운다. 코드·문서와 어긋나면 주석이 틀린 것으로 본다.
- **유지는 기록으로 끝난다.** 남기는 주석(또는 같은 사유를 공유하는 묶음)마다 사유 한 문장을 그 패스의 `passes/` 유지 목록에 적는다.

## 유지 대상

- **기계가 읽는 주석 — 시험 면제**, 지문·판정 모두에서 제외한다: `//go:build`·`nolint`·`eslint-`·`@ts-`·`/// <reference`·`# shellcheck`·`# syntax=`·`yaml-language-server:` 같은 도구 지시자(전체 목록은 `scripts/comment-policy/extract.sh`의 `DIRECTIVE`)와 이 레포 고유 `mock-exception:`(모킹 예외 표기 규약).
- **doc 주석 수준** — Go(`backend/`, 전부 `package main`)는 대문자 top-level 식별자의 식별자 이름으로 시작하는 1줄 doc 주석을 유지하고 패키지 주석은 요구하지 않는다. TS(`frontend/src`)는 export 함수·컴포넌트·타입의 JSDoc 요약 1줄을 유지한다. 테스트 파일(`*_test.go`·`*.test.*`·`*.spec.*`)과 `e2e/tests/support/`에는 요구하지 않는다. 이 수준이 요구하는 부분은 사유를 따로 대지 않고, 수준을 넘는 본문(`@param`·`@returns`, 시그니처·PRD·AC 조항을 되풀이하는 서술)은 시험을 받는다.
- **필요 사유가 있는 주석** — 이 레포에서 흔한 사유: SQLite 단일 writer 제약과 그 근거, S3 presign의 함정(공개 엔드포인트로 서명), 재시도 안전성·순서 계약, 테스트가 기대는 불변식, CI 환경과 운영이 갈리는 지점, Kubernetes API가 거부하는 조작, Vite 해시 자산과 캐시 헤더의 근거, Playwright와 `node:test` 러너 분리. 예시이지 면제가 아니다 — 이 종류라도 주석마다 사유를 댄다.

## 운영 규칙

- 판정 슬라이스는 원장의 판정 칸이 `완료`가 아닌 행을 파일 공유로 묶은 덩어리 단위로, 주석 400줄까지 한 번에 가져간다.
- **판정하지 않은 주석을 들이는 PR**은 자기 파일의 행을 더하거나 고치고 판정 칸을 `—`로 둔다. 이미 판정된 행의 파일에 주석을 더하면 그 행의 줄 수·지문을 갱신하고 판정 칸을 `—`로 되돌린다.
- 새 행을 표 끝에 덧붙이지 않는다 — 행은 범위 첫 파일 경로의 사전순이다.
- 원장 게이트 `python3 scripts/comment-policy/ledger_gate.py`가 `.github/workflows/comment-ledger.yml`에서 돈다. 파일 소속(유일·전수)·줄 수·지문·판정 칸 표기·표 밖 산문을 검사하고 집계를 출력한다. 미판정(`—`)은 실패가 아니다. 지문은 해당 파일·표면의 주석 본문 줄을 정렬해 이은 문자열의 sha256 앞 12자리다.
- 게이트의 실측은 `scripts/comment-policy/extract.sh`다. 범위·표면 규칙의 SSOT는 reconciler 모델이고 이 스크립트는 그 as-is 스크립트에서 지문 계산만 뺀 사본이므로, 모델이 개정되면 함께 맞춘다.

## 판정 절차

1. 원장에서 `—` 행을 덩어리로 골라 파일의 주석을 읽는다.
2. 주석마다 필요성 시험을 건다. 불필요하면 지우고, 더 나은 자리가 있으면 옮기고, 남기면 사유 한 문장을 적는다.
3. `passes/<판정일>-<slug>.md`에 제거 목록·유지 목록을 쓰고 원장 행(줄 수·지문·판정 `완료`)을 갱신한다.

## 범위 밖

범위는 레포 전체에서 제외 세 부류를 뺀 것이다 — ① 문서(`docs/`, 모든 `*.md`) ② 편집 불가(벤더·빌드 산출물·락 파일·생성 표식 파일) ③ 주석 문법 없음(JSON·JSONL 등 데이터, 바이너리). 이 레포 고유 제외는 없다.


## 지문 사각지대

MIXED·MARKUP 파일과 줄 중간 `#`이 주석이 아닌 HASH 파일의 줄 끝 주석, `*`로 시작하지 않는 블록 주석 연속 줄, Python 밖의 docstring 성격 문자열, 줄 스캐너의 문자열 추적 한계(JS 정규식 리터럴, JSX 텍스트의 따옴표·`//`). 오탐·누락 모두 결정적이다.
